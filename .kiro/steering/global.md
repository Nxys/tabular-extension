# 全局开发规则

## 语言规范

### 交流语言
- 所有回复必须使用中文
- 代码注释必须使用中文
- 文档和报告必须使用中文

### 代码规范
- 使用 TypeScript 严格模式
- 变量和函数命名使用英文（驼峰命名法）
- 注释和文档使用中文

## 测试规范

### 运行测试
- 使用 `npm test` 运行 Jest 测试（无需 `--run` 参数）
- 单元测试覆盖率目标：Background 层 90%+，Content 层 85%+

### 测试文件组织
- 测试目录：每个模块文件夹下的 `__test__` 目录
  - 例如：`src/background/__test__/`、`src/content/__test__/`
- 测试文件命名：`*.test.ts`
- 测试文件与源文件对应，例如：
  - 源文件：`src/background/usage.ts`
  - 测试文件：`src/background/__test__/usage.test.ts`

### 测试原则
- 不要自动添加测试，除非用户明确要求
- 用户要求运行测试时才执行测试命令

## 文件组织

### 目录结构
- 源码：`src/`
- 测试：每个模块下的 `__test__/` 目录（如 `src/background/__test__/`）
- 文档：`docs/`
- 报告：`docs/report/`
- 构建产物：`build/`

### 文档规范
- 所有报告文件必须放在 `./docs/report/` 目录
- 不要创建新的 markdown 文件来总结工作，除非用户明确要求
- 文档使用中文编写

## 代码风格

### TypeScript 规范
- 禁止使用 `any` 类型（除非必要且有注释说明）
- 所有导出的函数和类型必须有中文注释
- 使用明确的类型定义，避免类型推断的歧义

### 代码质量
- 遵循 ESLint 规则（配置在 `.eslintrc.cjs`）
- 保持代码简洁，避免冗余实现
- 优先使用函数式编程风格

## 工作流程

### 响应原则
- 简洁直接，避免冗长的总结
- 不要重复已经说过的内容
- 完成工作后用几句话说明结果即可，不要使用项目符号列表

### 效率优先
- 能并行执行的操作要同时调用工具
- 使用 `strReplace` 时分解为独立操作并并行执行
- 尽可能少的步骤完成目标

### 错误处理
- 遇到重复失败时，解释可能的原因并尝试其他方法
- 使用 `getDiagnostics` 工具检查代码问题，而不是执行 bash 命令
